# ISO/IEC 27001:2022 readiness

Alignment of this paper-trading stack against [ISO/IEC 27001:2022](https://www.iso.org/standard/27001) (ISMS clauses 4–10 and Annex A controls).

**This is not a certification claim.** Certification needs a documented Information Security Management System (ISMS), a Statement of Applicability (SoA), internal audit, management review, and an accredited certification body. This file is a **gap analysis** of what the repo and Azure/GitHub setup already evidence.

Related: [Cyber Essentials](./cyber-essentials.md) · [HLD](./hld.md) · [STRIDE threat model](./threat-model-stride.md) · [Firewall rules](../azure/FIREWALL_RULES.md)

**Scope:** Azure paper-trading dashboard (`crypto-trading-*`), GitHub CI, operator admin of those systems. Physical datacentre controls are **Azure shared responsibility**. Device / Entra / GitHub MFA items are **Org**.

Status key: **Aligns** | **Partial** | **Gap** | **Org** (operator / SaaS evidence) | **N/A** (not applicable; justify in SoA)

## Clauses 4–10 (ISMS) — mostly does not align

ISO 27001 certification fails without these, even if Annex A technical controls are strong.

| Clause | Requirement | Status | Evidence / gap |
|--------|-------------|--------|----------------|
| 4 Context | Scope, interested parties, ISMS boundary | **Partial** | Cloud boundary in [cyber-essentials.md](./cyber-essentials.md); no formal ISMS scope or interested-party register |
| 5 Leadership | Policy, roles, commitment | **Gap** | No information-security policy or appointed CISO/owner with ISMS duties |
| 6 Planning | Risk assessment, risk treatment, SoA, objectives | **Gap** | No risk register, treatment plan, or Statement of Applicability |
| 7 Support | Resources, competence, awareness, documented information | **Gap** | Runbooks exist (README, HLD); no competence records or controlled ISMS document set |
| 8 Operation | Plan and control processes, risk treatment | **Partial** | CI/CD and Terraform operate the stack; not run as a managed ISMS |
| 9 Performance evaluation | Monitoring, internal audit, management review | **Gap** | Security Scans are technical monitoring only; no internal audit or management review minutes |
| 10 Improvement | Nonconformity, corrective action, continual improvement | **Partial** | Trivy/CodeQL failures drive fixes; no CAPA log or ISMS improvement records |

**Certification blocker:** complete clauses 4–10 before pursuing an ISO 27001 audit.
